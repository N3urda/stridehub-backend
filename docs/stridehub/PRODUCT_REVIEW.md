# StrideHub 产品评审与改进

日期：2026-10-19。用户重点：每天使用顺手、训练计划与跑后复盘、健康数据记录与同步。

## 产品方向

现有功能已覆盖个人跑者的主要数据需求。当前更有价值的方向是缩短「打开今日 → 看清计划 → 执行 → 补记真实情况 → 复盘」的路径，并让断网、并发编辑和同步失败都能恢复。增加更多指标前，先保证每项信息能看懂、找得到、存得可靠。

## 本轮已实现

| 使用场景 | 原问题 | 改进 |
|---|---|---|
| 跑前看计划 | 今日页只有总时长和天气，步骤/补给藏在编辑器 | 按顺序展示分段与目标、补给时间和备注，可直达当前课次编辑；时长差异只作提示 |
| 首次打开 | 空页面主要提示去完整课表 | 提供安排训练、设置跑步习惯、导入已有运动的直接入口 |
| 补记旧训练 | 近期窗口外的待对账和待反馈难以找回 | 近7/30/90天、自定义日期与分页；更早待办提示、跨年导航 |
| 判断是否处理完 | 空反馈被当成已填；休息课要求反馈；重叠关联可能消失 | 统一四类待办与反馈有效性，保留明确的否/零，不自动推断漏训 |
| 保存遇到断网 | 服务器写入后响应丢失，再点保存可能重复创建 | 稳定草稿ID、读取核验、明确继续；冲突只合并实际改动 |
| 多端或AI同时修改 | 用户需理解原始数据，删除后的草稿难恢复 | 中文最新内容核对、保留草稿；已删除记录确认后另存 |
| 查看训练约束 | 简报要求核对原文却没有原文入口 | 简报直接显示所选课次日期适用的约束、来源与日期 |
| 查看健康趋势 | 编辑筛选或读取失败后旧睡眠图可能套用新日期 | 输入、请求、实际载入范围分开；每区块明确日期和覆盖情况 |
| 睡眠同步 | 进度停留、结果计数不可见、历史范围与同步范围混淆 | 有界轮询、手动刷新、结果计数与恢复指引，明确最近90天同步 |

## 建议下一步

1. **每周训练视图与周复盘。** 同屏安排一周、显示已计划与已关联的训练量，突出未完成记录和用户感受；先做可解释的回顾，再决定是否需要模板。拖动改期应预览日期/时间变化，遵循现有版本冲突规则。
2. **健康报告人工核对界面。** 将已有结构化健康背景提供给用户查看和修订，保留原报告、医生意见、AI解读及待核对状态，避免把一次提取直接当成确认结论。当前仍由API/Skill维护。
3. **运动分析的返回与筛选记忆。** 保留筛选、页码和返回位置，区分首次无数据与筛选无结果；本轮未改该页面。
4. **Android会话恢复与当前位置。** 启动离线时直接重试已有会话，底部导航显示选中项，设计会话过期后的草稿恢复。当前本轮改善随后端网页生效，未修改原生APK。

这些是后续候选，未纳入本轮已完成功能。暂不新增自动训练处方、恢复评分、社交排行榜或全自动覆盖课表；当前数据缺失和个人习惯尚不足以支撑这些功能的可靠体验。
