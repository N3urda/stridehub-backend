# Mobile weight collection v1

All requests use HTTPS in production. Pair through native HTTP using the authenticated WebView session Cookie: GET `/admin/health/api/collection/csrf` returns `{csrfToken}` (health CSRF); POST `/admin/health/api/collection/devices` JSON `{name:"My phone"}` with Cookie and `X-CSRF-Token` returns `{deviceId,name,token}`. Token is returned once. Store in Android encrypted storage. No admin API key on phone. GET same devices route returns `{devices:[{deviceId,name,revoked}]}`; DELETE `/admin/health/api/collection/devices/{deviceId}` revokes with CSRF.

Device routes use `Authorization: Bearer <token>` only:
- PUT `/device/v1/weight/{measurementId}` creates immutable measurement, or replays same canonical payload; response `{measurement, replayed, projection}`. UUID must match body's measurementId. 409 changed payload or deleted UUID; deletion cannot be undone by replay.
- GET `/device/v1/weight/{measurementId}` returns `{measurement}` for own device, 404 otherwise, including tombstone when deleted.
- GET `/device/v1/weight?offset=0&limit=50` returns `{records,total,offset,limit}` own records including tombstones, UTC measuredAt descending then measurementId descending.

JSON body (32 KiB maximum):
```json
{"measurementId":"a0000000-0000-4000-8000-000000000001","measuredAt":"2026-10-21T08:00:00+08:00","localDate":"2026-10-21","weightKg":75.2,"fatPercent":null,"bmi":null,"impedanceOhms":null,"profile":{"heightCm":175,"birthYear":1990,"sex":"male"},"derived":{"algorithmVersion":"yunmai-v1","values":{"bmi":24.55}}}
```
Required: measurementId, measuredAt (ISO with explicit offset), localDate, weightKg (2..300), profile object, derived object with nonempty algorithmVersion and values object. Missing optional numeric fields normalize to null, never zero. Profile is an immutable JSON object snapshot; derived values are a versioned JSON object snapshot. Nullable fatPercent 0..100, bmi 1..100, impedanceOhms 0..5000. Unknown top-level fields rejected. No schema migration or recalculation on replay. measuredAt identifies the instant; localDate independently preserves the original captured calendar day. Historical imports may have a different localDate from the supplied offset (original timezone may be unknown). New Android captures should persist their original offset. Never infer an original timezone for historical imports.

Admin Cookie+CSRF or existing admin API bearer: GET `/admin/health/api/collection/weight` or `/api/v1/health/collection/weight` paginated history; DELETE same `/{measurementId}?deviceId=...` creates tombstone. API key routes retain existing authorization. Device credentials cannot access these or other admin/API/MCP routes.

Projection response `{status:"projected"|"manual_conflict"|"unchanged",measurementId}`: latest surviving capture per local day projected to existing weight history in kg converted to configured units. Existing non-collection daily entries preserved and report manual_conflict. Deletion recomputes day. Manual edits thereafter remain protected. Capture immutable data is retained independently; manual projection conflict does not discard capture. A storage/concurrent-write failure rolls back the transaction and can be retried with the same measurementId. Errors use existing `{error:...}` envelope with HTTP 401/403/404/409/413/415/422. limit 1..100; offset 0..100000.


Android recovery extension: CSRF-authenticated POST devices also accepts optional `deviceId` (32 lowercase hexadecimal characters). An existing ID rotates/reactivates its credential atomically through optimistic version checking, invalidating the previous token and retaining the same immutable measurement namespace. An absent ID is created; clients may persist a random candidate before the first request, so uncertain pairing responses can be retried without creating a second namespace. This remains an admin-only action under the installation's existing single-admin authorization, never device bearer authorization. Android remembers this nonsecret ID separately per exact installation URL and login username; explicit re-pair only renews that same destination/account. A different server or username gets a distinct candidate and cannot implicitly adopt old local queue entries.

Android frozen `derived` retains `source`, `calculationBasis`, `calculatedAt` (epoch milliseconds), `profile` (original calculation profile object), `bodyShape`, `grades`, `references`, and `scores`, in addition to `algorithmVersion` and `values`. Metric maps use the existing uppercase Android metric enum keys. `fatPercent` can be an estimate from impedance; display calculation basis rather than claiming direct body-fat measurement. Raw BLE packets and Bluetooth addresses remain local. Imported `localDate` remains independent from the UTC representation used when historical timezone is unknown.

## Read-only daily workspace

Authenticated GET `/admin/health/api/collected/{topic}` and `/api/v1/health/collected/{topic}` accept `topic=weight|zepp`, required `from`/`to` (maximum 366 days), `limit=1..100` (default 20), `offset`, and `snapshot`. First page returns `records,total,nextOffset,snapshot`. Subsequent pages require that snapshot; changes return 409 and require restarting at offset 0. Optional `kind` filters Zepp sources. No device tokens or provider payloads are returned. Device bearer tokens do not authorize these admin/API routes.

Weight records preserve every capture, original localDate, frozen calculation/profile data, tombstones, and `projectionStatus=manual_conflict|daily_projection`. The status describes daily-record ownership, not proof that every capture is the selected daily value. `updatedAt` is the server's most recent write, including deletion; it is not the original arrival time.

Zepp summaries return separate SDNN and RMSSD fields, known scalar summaries, sample counts, source date/date basis, and availability notes. `dateBasis=utc_event` uses the event's UTC calendar date; `source_calendar` uses a provider calendar date. Undated profile snapshots remain included and marked `date=null`, so consumers must not attribute them to a requested day. Encoded respiratory, readiness and charge records are availability-only until their format and meaning are verified. Heart-rate file indices do not imply downloaded waveforms; ODI/OSA is not spot SpO2. No raw source is fetched by the browser summary list.

MCP retains its nine existing tools and authorization. `get_history` adds read-only topics `weight_captures` and `zepp_summaries`, sharing its existing from/to/timezone/snapshot pagination contract. The former exposes per-capture detail; the latter excludes provider raw samples and identifiers. Existing `weight` still reads the protected daily projection. No new MCP write operation is added.

The body page links capture history, source summaries, device authorization/revocation, existing profile/unit settings, and existing running CSV export. The Android package has **not** been released; the page intentionally offers no APK download URL. Server backup remains a NAS administration operation, not a new web feature. This change does not build or deploy an APK or image.
