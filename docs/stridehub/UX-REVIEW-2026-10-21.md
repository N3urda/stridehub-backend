# Web 与 Android 看板、采集交互审视

审视开始：2026-10-21，验收完成日期见 VALIDATION.md。范围：现有产品的查看、记录、核对和失败恢复流程。沿用后端数据模型、账号隔离与不可变采集协议。

## 产品判断与改动

| 原问题 | 用户影响 | 本次改动 |
| --- | --- | --- |
| 总览以图表为主，没有日常记录入口 | 需要先猜记录属于哪个模块 | 首屏提供体重、饮食、今日训练与反馈、手机采集入口；体重与饮食直接打开当日表单 |
| 切换范围后，失败来源只清掉一个容器 | 新日期范围下仍显示旧曲线、睡眠阶段或运动列表 | 按来源清理全部关联展示，分别标明读取中、读取失败、没有记录；请求代次保护晚到响应 |
| “最近”与“今天”、采集时间与入库时间混用 | 容易把历史测量当作实时状态 | 最近体重说明所选期间，活动热量独立采用其有效测量日期，逐次称重明确测量时刻和服务器回执 |
| 计划入口丢失对应日期 | 点某天训练后还需重新找日期 | 跳到该天的训练日程；指标明细保留总览日期范围 |
| 刷新后的同步按钮被无条件重新启用 | 未连接或仍在同步时仍可重复操作 | 由最近读取的连接状态统一控制按钮，连接状态未知时不可提交 |
| Android 默认今日页、旧导航与 Web 总览结构不一致 | 同一个产品需要学习两套入口，WebView 又重复显示导航 | Android 默认总览；五项原生导航为总览、身体、运动、计划、采集；更多保留饮食、减重与今日执行；WebView 使用原生导航 |
| 称重页大数值优先于采集动作，保存和上传状态分散 | 找连接/手动记录困难，容易把仅本机保存误作上传完成 | 连接秤与手工记录前置；首页、历史及详情分别展示本机保存和 NAS 状态；补录后展示刚保存的测量 |
| 实时秤读数旁仍可打开上一条记录详情 | 实时值和已保存记录混淆 | 实时读数标明尚未保存，同时隐藏旧记录详情入口 |
| 表单错误只弹提示，部分初次读取失败无法恢复 | 用户不知改哪里，重试容易丢草稿 | 原生输入错误定位到字段，手工采集保留旋转前的草稿；Web 体重支持保留输入后重新读取，已核验未修改内容禁止重复保存 |
| 原始来源说明、设置和日常数据平铺 | 手机页面较长，重要状态不突出 | 来源档案折叠，采集回执以体重/测量时刻/接收状态为主；说明展开后可查；交互目标与次级文本可读性改善 |

## 数据与实现约束

- 不把缺失值填成零，不根据页面设计生成健康评分、疾病判断或计划建议。
- 每次采集与每日趋势分别保留；手机上传不覆盖已有手工日记录，删除标记仍阻止重传恢复。
- 只在专用测试数据库中写入 DEMO 资料。浏览器故障及同步状态验收使用明确的响应拦截，没有向真实 Zepp 账号发起同步。
- WebView 客户端标记只控制外壳展示，不参与鉴权；登录表单、同源边界、证书校验和跨账号队列限制保持有效。
- 本次合并代码与测试，不改变 NAS 部署、现有数据库或手机正式安装。

## 验收入口

- `tests/e2e/overview-browser.cjs`：总览、快捷记录、日期链接、整组错误恢复、同步按钮、移动布局和 Android WebView 外壳。使用 8091 与 `tests/dreeveworkspace-browser.db`。
- `tests/e2e/workspace-browser.cjs`：既有饮食、减重、日程、草稿、并发冲突、键盘/触屏和布局回归。与总览脚本共享专用端口和库，顺序运行。
- `tests/e2e/collection-ui-browser.cjs`：身体与采集页的读取恢复、逐次采集、翻页、删除回执和布局。使用 8092 与 `tests/dreevecollection-ui-browser.db`。
- Android：`testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest`，以及专用调试模拟器上的仪器测试。测试使用调试包，不操作正式包或个人设备。

最终验收结果与实际边界记录在 [VALIDATION.md](VALIDATION.md)。浏览器截图均为 DEMO 数据，保存在忽略的 `var/runtime/` 下。
