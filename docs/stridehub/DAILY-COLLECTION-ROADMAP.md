# StrideHub 日常采集整合任务

建立日期：2026-10-21。目标：用户在 StrideHub 管理全部日常健康采集；NAS 是统一数据中心，Android 是可离线使用的蓝牙采集端，TinyYumi 不再作为独立产品维护。

本轮完成现状核对和任务拆分。以下实现、合并、发布均待逐阶段完成，不能把本文件当作上线完成记录。用户已授权实现、合并 main 和部署 NAS，无需每阶段重复申请授权。真实手机安装/上秤等用户操作，接近验收时再协调。

## 已核实的起点

- origin 默认分支为 main；当前工作分支 codex/zepp-events-identity，包含已部署但尚未合并的 Zepp 修复与扩展同步。开始整合前重新获取远端并核对差异。
- NAS 已验证近 90 天 Zepp 回填，新增来源保存为原始数据；对应网页卡片尚未齐全。当前部署及验证见 var/runtime/zepp-expanded/DEPLOYMENT-zepp-expanded.md。
- TinyYumi 位于相邻 tinyyumi 仓库，原生 Java + SQLite，已有云麦蓝牙称重、历史、趋势、身体成分估算和导出。AndroidManifest 尚无 INTERNET 权限。
- Android applicationId 为 io.tinyyumi.scale，当前 versionCode 5。保持安装身份和原发布签名，避免要求卸载后丢失数据；产品显示名称可以改为 StrideHub 采集。
- StrideHub 现有 WeightRecordService 按日期保存，需要新增每次测量的数据模型，兼容原来的日体重消费者。

## 目标体验

手机称重 → 本地先保存 → 自动上传 NAS → 网页当天出现记录与趋势 → 手机显示“已同步”。NAS 不可达时继续称重，恢复连接后补传；用户能查看等待、失败原因并重试。

网页以“今日要做什么、今天采集齐了吗”为入口。健康趋势承载指标与历史，训练/饮食保留现有能力，设备与设置集中管理 Zepp、手机、体脂秤和同步状态。避免把原始 JSON 或算法细节放在日常操作路径上。

默认先完成家庭局域网和现有 NAS 的连接。外网访问作为独立配置项，不自动开放路由器端口或将 NAS 发布到公网。

## 分阶段任务与验收

### P1 — 补齐健康数据展示，形成第一批可上线改进

状态：待实施。依赖：无。

- [ ] 将已保存来源整理为有来源说明的读取模型：身体电量、压力、SDNN/RMSSD、呼吸、PAI、恢复、训练负荷、VO2max、乳酸阈值、每日活动、血氧等。
- [ ] 补齐概况卡、趋势、日期范围和详情；逐项核实真实字段、单位、时间与缺失值。算法估算与实测分开，SDNN 与 RMSSD 分开，皮温偏差不写成绝对体温。
- [ ] 为没有记录、授权失败、同步中、数据过旧、仅有文件索引分别给出可理解的提示；逐秒心率索引不显示成已有逐秒曲线。
- [ ] 增加数据源/采集管理入口：最近成功时间、覆盖日期、重试与同步结果；长同步可恢复，不让页面长期假装进行中。
- [ ] 验证桌面与手机宽度、日期切换、缺失数据和失败恢复，以及 NAS 实际数据。
- [ ] 审查当前 Zepp 分支与远端 main 差异，合并、推送 main，备份并部署 NAS，核对镜像修订和持久化数据。

完成标准：用户能在 NAS 网页找到所有已接入来源的可解释展示或明确可用性说明；main 与已部署版本可追溯，核心流程通过真实浏览器验收。
