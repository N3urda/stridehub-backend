# Android 0.3.0 原生改造验收

本轮把 Android 主页面、登录、业务表单、图表、文件操作及同步入口改为 Kotlin/Compose 原生界面，保留 Java 称重、蓝牙协议、身体成分计算与原 SQLite 数据。正式包名仍为 `io.stridehub.app`，versionCode 从 2 升至 4。

验收日期为 2026-10-23 至 24 日，实施分支为 `codex/native-android`，基线 `fb657020c`，最终应用源码 `9b04b4f8b`。这里记录实际执行过的验证，不能据此推定已部署 NAS 或已在用户手机上验收。完整功能边界见 [设计](../superpowers/specs/2026-10-23-native-android-design.md)，安装、接口和守护进程要求见 [Android README](../../android/README.md)。

## 环境与数据隔离

- 专用 Android 15 / API 35 arm64 模拟器 `stridehub_native`，设备 `emulator-5556`，调试包 `io.stridehub.app.debug`；未操作用户正式 App 安装。
- 本地测试后端 `stridehub-native-e2e`，只监听 `127.0.0.1:8086`。容器必须带 `STRIDEHUB_NATIVE_E2E=1`，数据库为 `var/native-e2e/db`，`watch` 单独挂载为 `var/native-e2e/watch`。
- PHP 集成测试在另一隔离容器 `stridehub-native-test` 内运行，PHP 8.5.10，独立测试数据库。未访问生产 NAS 数据库、已有文件或 Zepp 凭据。
- 所有运动、身体、计划与账号均为 DEMO 合成夹具。API 观察会话在脚本结束时撤销；账号文件、数据库、截图、日志和 APK 均在忽略目录 `var/native-artifacts/`。
- 原生 UI 验收通过 Android 控件树定位并点击控件；控件树检查没有 WebView。服务端写入结果再通过真实 JSON API 或本机 SQLite 核对。

### 原 APK 覆盖升级

使用实际旧版 0.2.0 调试 APK 初始化合成数据，旧版本自身完成已有衍生指标回填后冻结基线，再覆盖安装新版本。逐行比较 `measurements`、`measurement_derivations`、`legacy_imports`、`sync_queue`：5 条测量、原 UUID/时间/衍生指标、5 种队列状态及原目的地/冻结载荷、1 条删除墓碑全部相同。

升级结果为 PASS，规范化数据摘要 `4a7238b906360a9046bb22e905a321ef9d8a4f2f801d67fd6513c620349b8e97`。这是旧版到新版的实际覆盖安装检查；正式签名兼容性另行核对，不能把调试包升级当作用户手机实测。

### 跑步分析夹具

`tests/e2e/seed-native-run.py` 经真实上传与文件导入生成 5 km、2,000 秒、201 个采样点的跑步，包含 10 秒显式暂停。已有后端分析返回 200 个散点、5 个心率区间、5 个公里分段、6 项最佳片段及周/月/日统计；未知功率保持 null。原骑行、Zepp 与其他测试运动保留。

该真实导入夹具已在原生 App 打开：跑步复盘、周跑量、活动日历、最佳片段、详情散点、区间/心率分布、数据覆盖、GAP 分段与跑步课表选择均可达。缺失传感器与分段的情况另由原生仪器测试验证。

## 自动检查与回归

后端相关集成集执行通过：**274 个测试、1,703 个断言**，覆盖移动会话、移动工作流、健康/训练、共享运动删除和 daemon。各子任务重复运行的用例包含在相关集合中，不累加成独立测试总数。

最终原生构建的 `testDebugUnitTest`、`lintDebug`、`assembleDebug`、`assembleDebugAndroidTest` 和源代码门禁全部通过：**37 个单元测试，0 失败/错误**。原称重算法包装测试还执行 2,446 组参考案例、17,122 次浮点位比较。

API 35 模拟器执行 **39 个仪器测试全部通过**，包括原生会话、账号缓存隔离、Room 保存确认防覆盖、表单、独立导航、完整/缺失跑步分析、状态栏/称重主题、称重离线入口、BLE 生命周期、旧库和上传回执。随后单独重复 CSV 导入/回放测试，再次通过。

`tools/verify-native-apk.py` 扫描 APK 内全部 DEX 的 WebView 构造/网页导航、脚本执行及 CookieManager 调用，覆盖依赖库。旧版 APK 作为反例被拒绝，报告 30 处浏览器相关调用；最终调试包 10 个 DEX、正式包 2 个 DEX 均通过门禁。门禁只证明约束边界，不能替代功能验收。

曾尝试的整个仓库大测试集有既有夹具、地理数据和静态资源相关失败；本报告不声称整个仓库测试全绿。API 35 强制透明状态栏造成的一条新主题测试预期已修正。旧 CSV 仪器测试重复运行时还暴露测试上下文未真正隔离 SQLite 的问题；改为每次专用数据库路径，并断言实际打开路径和空墓碑表后，完整集合和单独重复运行均通过。该修正仅改测试，没有重建生产称重数据库。

独立审查覆盖后端鉴权、工作流、原生客户端、称重集成和全分支。原生运行分析/来源/编辑刷新与关联资格问题已修复并复核；历史运动关联的复核使用按 ID 查询，避免把最新 500 条候选列表误认为全部运动。验收脚本另经审查，补充当前服务器/账号校验、真实重连断言及密码命令异常脱敏；迁移测试隔离也已复核。

实施时按文件职责并行完成前后端，再通过整合验收解决接口和时序风险。称重保留独立原生 Activity，去除重复主导航并统一会话/主题，复用原蓝牙生命周期和数据层；代价是称重与 Compose 主界面仍有内部实现边界，今后进一步统一交互时可能需要调整该边界。

## 可复现入口

```sh
# 只用于上述专用模拟器与隔离后端；先准备 DEMO 夹具。
python3 tests/e2e/native-android.py \
  --credentials var/native-artifacts/acceptance-login.json --scenario all

# 生成含传感器数据的跑步，检查实际导入与分析结果。
python3 tests/e2e/seed-native-run.py \
  --credentials var/native-artifacts/acceptance-login.json
```

`native-android.py` 自动覆盖登录/导航、饮食 CRUD、计划反馈、离线恢复、同步和退出；文件选择器导入/GPX 导出、配对与手工称重冲突另有本轮实际操作记录，不伪称由这条命令全部自动完成。升级脚本 `native-android-upgrade.py` 的 seed/verify 需要分别安装真实旧版与新版 APK，且只允许专用调试模拟器。
