# 体检报告与健康背景

本工作流将用户提供的报告整理成可追溯的背景，辅助生活安排和训练规划。它不是诊断、处方或运动许可评估。原文件由用户提供的会话/文件环境处理；本 API 仅保存结构化摘要，不接收 PDF/图片文件。

## 阅读与核对

使用当前环境可用的文档/图片工具读取原材料。保留报告日期、来源名称、项目名、原始值、单位、该报告的参考范围及页码。结果可以是数字、阴性/阳性或定性描述，所以 API 的 `valueText` 保留原文。OCR 不清楚时不要猜小数点、符号或单位；先列出待核对内容。

检查缺页、跨年报告、不同单位与不同实验室参考范围。不根据另一家实验室或网上的范围替换原报告范围；趋势比较前明确口径。旗标 `flag` 优先照录报告，无法判断时用 `unknown`，不能因为空值就标记正常。

参考依据：[美国国家医学图书馆 MedlinePlus：如何理解化验结果](https://medlineplus.gov/lab-tests/how-to-understand-your-lab-results/)。化验结果需要结合病史、症状和临床评估；范围内/外不能单独确定是否患病。实际解读特定结果时另查相关可靠医学资料，标明适用条件，不凭本文生成诊断。

## 事实、医嘱与解释

- `findings`：原报告观察结果；字段为 `name`、`valueText`、`unit`、`referenceRangeText`、`flag`、`page`。没有单位/参考范围时保留空文本，不补造。
- `clinicianAdvice`：报告或用户明确转述的医生建议原文。不能将 AI 的建议改写后放入这里。
- `aiInterpretation`：AI 对已有材料的解释与不确定性，明确依据，避免确定性诊断。
- `needsReview`：提取仍需核对时为 true；它表示材料提取状态，不代表医生是否审核、治疗是否完成或适合运动。
- `notes`：来源局限、模糊项目及必要说明。只保存本次管理所需信息，避免身份证号、住址、检查条码等无关身份资料。

保存健康背景属于用户要求的建档/更新任务时，使用已有授权；上传报告本身不授权将原文件发送到其他服务。读取已有背景，按 ID 合并新增或修改的报告，保留无关报告、约束和偏好。不要把身体状态量表编成任意值以便将报告塞进每日 check-in。

## 最小保存结构

先 GET `/api/v1/health/context`。报告最多 30 份，每份至少有 `id`、`title`、`reportDate`（YYYY-MM-DD）和 `sourceLabel`。下面是**虚构的格式演示，不是用户报告，不得直接写入个人实例**：

```json
{
  "version": 0,
  "reports": [{
    "id": "example-report",
    "title": "格式示例",
    "reportDate": "2026-09-20",
    "sourceLabel": "用户提供的报告第 2 页",
    "findings": [{"name":"示例项目","valueText":"阴性","unit":"","referenceRangeText":"阴性","flag":"normal","page":2}],
    "clinicianAdvice": [],
    "aiInterpretation": "",
    "needsReview": true,
    "notes": "虚构格式示例"
  }]
}
```

在真实更新中使用最新 `version`，并提交合并后的完整 `reports` 数组。API 默认补齐可选空字段，未知字段会被拒绝。GET 核验后才能说“已保存”；未提供报告、未写入或服务未部署时，明确说明没有健康档案。

## 约束与日常偏好

`constraints` 每项含 `id`、`description`、`sourceType`（`clinician` 或 `user`）、`sourceReportId`（关联报告 ID 或 null）、`validFrom`、`reviewOn`、`status`（active/inactive）。不要将 AI 提议伪装成任一来源；提议留在对话或 `aiInterpretation`，用户明确采纳后才能记为 user 来源。用户采纳不将其变为医嘱。

“复评前避免剧烈运动”保留为来源明确的限制，不扩写成报告没说过的剂量/病名；没有复评结果时不安排与之冲突的强度，也不因 reviewOn 已过自动解除。存在冲突时指出原建议、日期和需要澄清的具体问题。

`lifestylePreferences` 是字符串列表，存用户的作息、饮食偏好、可用时间和明确采纳的日常目标。更改时合并保留旧项；它不是自动执行的日程、监测指标或医学处方。健康字段不会由服务器自动判读或拦截所有不合适的训练，规划时必须主动读取并考虑。

## 健康建议边界

结合当前症状、近期训练与报告日期提供有条件的解释，不能把旧体检当作今天的 readiness。不开立/停用/调整处方药，不凭单个异常指标推荐治疗剂量。若用户报告当下胸痛、晕厥、严重呼吸困难等可能紧急的症状，暂停训练规划，优先建议及时获得当地急救/医疗评估。

需要医疗专业人员判断时说明具体原因，并继续能安全完成的资料整理与问题清单，不用泛化免责声明替代实际帮助。
